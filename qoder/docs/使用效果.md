# 使用效果（模板 + 采集方法）

> 题面把「使用效果」列为**鼓励提交**，但也是评价维度之一（3.2）。
> 关键不是数字多大，而是**数字有来源、能核对**。本文给出采集口径和一张空白表，
> 数据由你在真实使用后填写；没有的数据就写「暂无」，不要编。

---

## 一、现在就能采集的三类数据

| 数据类型 | 来源 | 采集方法 |
| --- | --- | --- |
| 使用次数 / 用户数 | PowerContext artifact 计数 | `python -m duban state --json` 里的 `stats.turns`；多人使用时按 `DUBAN_USER` 分别统计 |
| 检索规模 | seekdb 表统计 | `python -m duban state` 的「资料 7 篇 / 片段 275」；换自己的语料后数字会变 |
| 网站访问 | Qoder Sites 访问统计 | 站点面板 → 访问统计，截「访问次数 / 独立访客」 |

一条命令导出使用量：

```bash
python -m duban state --json | python -c "import json,sys; s=json.load(sys.stdin); print(s['stats'])"
# {'documents': 7, 'chunks': 275, 'weak': 2, 'turns': 9}
```

## 二、提效对比怎么做才算数

不要写「效率提升 80%」这种没有过程的数字。用同一件任务、同一份资料，计时对比：

| 任务 | 手工做法 | 用读伴 | 计时方式 |
| --- | --- | --- | --- |
| 在一篇 18 页论文里找某个概念所在页 | 打开 PDF，Ctrl+F 猜关键词，翻 3–5 次 | 提问一次，点引用直接跳到页 | 秒表，各做 5 次取中位数 |
| 复习上周没懂的概念 | 翻聊天记录 / 笔记，靠回忆 | `duban review` 直接列出来 | 记录耗时与是否找全 |
| 接着读上周停下的资料 | 重新翻到大概位置 | `duban state` 显示「读到 6/16 页」 | 记录找位置耗时 |

> 建议做 3 个人 × 3 个任务的小样本，把每次耗时记在表里，取中位数。
> 人少没关系，**过程可核对**比样本大更重要。

## 三、用户反馈怎么收

- 让 2–3 位同学各用 15 分钟，问三个问题：
  1. 哪一次回答让你觉得「这就是我要的那一页」？
  2. 哪一次它答错了或没找到？当时你问的是什么？
  3. 你会不会在下次读论文时继续用？为什么？
- 收集方式：微信/问卷都行，截图或导出 CSV，**隐去姓名与联系方式**再提交。
- 把反馈转成迭代记录：例如「三个人都提到英文论文里中文提问找不到 → 加了术语表
  `duban/glossary.py`，Hit@3 从 0.62 提到 0.90」。
