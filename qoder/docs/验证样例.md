# 验证样例

> 三组样例，每组都能在十分钟内做完，并且**不依赖任何模型 Key**。
> 每组都写清楚：初始数据 → 输入 → 操作步骤 → 预期结果 → 指定技术在哪一步起作用。

前置：已完成 [`运行说明.md`](运行说明.md) 的安装与 `python -m duban init`。

---

## 样例 A：中文提问命中英文论文的第 8 页

**目的**：证明「检索真的在起作用」，而不是把问题原样丢给模型。

**初始数据**：`corpus/papers/raft.pdf`（18 页）、`corpus/notes/raft-notes.md`。

**输入**

```bash
python -m duban ask "Raft 的 Figure 8 说明了什么问题？" --json
```

**操作步骤**

1. 执行上面的命令；
2. 看输出里 `citations[*].citation` 与 `page` 字段；
3. 打开 `corpus/papers/raft.pdf` 第 8 页，确认 Figure 8 就在这一页。

**预期结果**

- 引用里出现 `papers/raft.pdf#p9` 或 `#p8`（Figure 8 与讨论跨这两页）；
- `records/db/queries.jsonl` 新增 3 条 `search` 记录，`rows` 都 > 0；
- 回答正文是英文原句，说明它是从 PDF 里抽出来的，不是生成的。

**指定技术的作用**

| 技术 | 这一步做了什么 | 怎么核对 |
| --- | --- | --- |
| seekdb | 用 `MATCH(searchable) AGAINST (…)` 在 273 个片段里取候选，分数由数据库算 | `records/db/queries.jsonl` 最后 3 行 |
| PowerContext | 读取画像决定给几条要点；写入本次问答摘要 | `records/memory/events.jsonl` 里 `op=turn` |

## 样例 B：薄弱点改变了下一次回答

**目的**：证明 PowerContext 的记忆**被使用**，而不只是被写入。

**初始数据**：同上。

**输入**

```bash
# 1. 标记一个薄弱点
python -m duban mark "CAP" --note "分不清 CAP 与 BASE 的取舍"

# 2. 提一个和它相关的问题
python -m duban ask "CAP 定理到底限制了什么？"
```

**操作步骤**

1. 先把 `DUBAN_USER` 设成一个新用户（`export DUBAN_USER=demo2`，Windows 用 `set`），
   保证是干净的记忆；
2. 不加标记先问一次，记录输出；
3. 执行 `mark`；
4. 再问同一个问题。

**预期结果**

- 第二次输出多出一行 `记忆：你之前标记过「CAP」没看懂，这次先补一条更基础的说明。`；
- 回答下方多出一段「先补一条基础说明」，引用来自与 CAP 定义相关的片段；
- `python -m duban state` 的「薄弱点」里出现 `CAP ×1`。

**指定技术的作用**

| 技术 | 这一步做了什么 | 怎么核对 |
| --- | --- | --- |
| PowerContext | `mark` 写一条 `duban.weak` artifact；提问时读回并触发补正召回 | `records/memory/events.jsonl` 的 `op=weak` 与随后的 `op=turn` |
| seekdb | 补正召回同样走一条 `MATCH … AGAINST` | SQL 日志里多出一次 `search`，参数是 `CAP` |

## 样例 C：重启之后记忆还在

**目的**：证明记忆是**持久化**的，不是进程内的全局变量。

**输入**

```bash
python -m duban touch papers/dynamo --page 6 --ratio 0.375
python -m duban state          # 记下「Dynamo … 读到 38%」
# 关掉终端（或换一个 shell / 重启机器）
python -m duban state          # 再跑一次
```

**操作步骤**

1. 记录第一次 `state` 输出里 Dynamo 的进度；
2. 结束所有 python 进程（`pkill -f duban`）；
3. 重新执行 `python -m duban state`。

**预期结果**

- 两次输出的进度一致（`读到 38%`）；
- `python -m duban review` 的清单里，Dynamo 出现在「没读完」，并带 `读到 6/16 页`；
- `records/memory/events.jsonl` 里能数出对应的 `op=progress` 记录。

**指定技术的作用**

| 技术 | 这一步做了什么 | 怎么核对 |
| --- | --- | --- |
| PowerContext | 进度以 `duban.progress` artifact 追加写入，读取时取该文档最大 `seq` | 两次 `state` 输出一致 |
| seekdb | 文档页数、片段数来自 `duban_documents` / `duban_chunks` | `python -m duban state` 里的「16 页」 |
