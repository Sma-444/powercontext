# 运行说明

> 目标：评审在一台干净机器上，只照这份文档就能从零跑通读伴，并核对 seekdb 与 PowerContext 各自起了什么作用。

## 1. 环境要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Linux x86_64 / macOS / Windows | 开发与验证在 Ubuntu 22.04 完成 |
| Python | 3.12（3.11+ 亦可） | `powercontext[seekdb]==1.5.0` 需要 3.11+ |
| 内存 | ≥ 2 GB | 273 个片段，嵌入式库，无外部服务 |
| 磁盘 | ≥ 300 MB | 依赖约 120 MB，语料约 1.5 MB |
| 网络 | 仅安装依赖时需要 | 运行、检索、评测全部离线 |
| 外部服务 | **不需要** | 不需要 OceanBase 实例、不需要模型 API Key |

## 2. 安装

```bash
cd qoder
python -m venv .venv
. .venv/bin/activate            # Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -U pip
python -m pip install -r requirements.txt
```

`requirements.txt` 只有五项：

```
powercontext[seekdb]==1.5.0   # 带嵌入式 seekdb 的 PowerContext
pypdf==7.0.0                  # PDF 文本层抽取
PyYAML==6.0.2                 # 评测集与资料清单
jieba==0.42.1                 # 中文分词（PowerContext 本身也依赖它）
pytest==8.4.2
```

安装完成后自检：

```bash
python -c "import powercontext, pypdf, yaml, jieba; print('deps ok')"
```

## 3. 建库与导入

```bash
python -m duban init
```

预期输出：

```
索引就绪：7 篇 / 275 个片段
```

这一步做的事：

1. 在 `.runtime/seekdb/` 创建嵌入式 seekdb 实例（目录由 `DUBAN_DB` 覆盖）；
2. 建 `duban_documents` / `duban_chunks` 两张表，并在 `searchable` 上建
   `WITH PARSER NGRAM` 的全文索引；
3. 逐篇解析 `corpus/`：Markdown 按标题切小节、PDF 按物理页切块，记录页号 / 行号；
4. 写完把每条 SQL 追加到 `records/db/queries.jsonl`。

想换自己的资料：把文件丢进 `corpus/`（支持 `.md` / `.txt` / `.pdf`），再跑
`python -m duban ingest`。增量导入只处理 revision 变了的文件。

## 4. 提问

```bash
python -m duban ask "Raft 的 Figure 8 说明了什么问题？"
```

输出结构（示例）：

```
问：Raft 的 Figure 8 说明了什么问题？
答：在《Raft: In Search of an Understandable Consensus Algorithm》等 4 份资料里找到 5 处相关段落，下面每一条都能点回原文。
记忆：上次你问的是「……」，这轮接着往下走。

  [1] ……原文句子……
      ↳ papers/raft.pdf#p9  (Raft: In Search of an Understandable Consensus Algorithm)
  ...
  检索：候选 61 条 → 引用 5 条 · 词项：raft, figure, 8, 说明, 问题
```

需要机器可读结果时加 `--json`。

## 5. Web 界面

```bash
python -m duban serve --host 127.0.0.1 --port 8765
```

浏览器打开 `http://127.0.0.1:8765`。

- 默认只监听本机；要对局域网开放用 `--host 0.0.0.0`（**没有鉴权，别暴露到公网**）。
- 分享/截图用：`http://127.0.0.1:8765/?preload=1&q=<问题>`，
  服务端会把状态与答案直接内联进 HTML，首屏就有内容。

## 6. 记忆与复习

```bash
python -m duban mark "CAP" --note "分不清 CAP 与 BASE 的取舍"
python -m duban profile --depth deep
python -m duban touch papers/dynamo --page 6 --ratio 0.375
python -m duban state            # 看资料库 / 记忆 / 复习清单
python -m duban review           # 只打印复习清单（state 的子集）
```

这些写入都落在 PowerContext 的 `atomic-memory` 里，作用域默认 `duban:demo`，
按 `DUBAN_USER` 隔离。**杀掉进程再打开，内容还在**——这是「记忆能复用」的最小证明：

```bash
python -m duban state | head -20
# 换一个终端、甚至重启机器后再跑一次，输出一致
```

## 7. 测试与评测

```bash
python -m pytest           # 9 passed
python -m duban eval       # 生成 records/eval/report.{json,md}
python -m duban demo       # 端到端演示（会重建索引）
```

`eval` 的标注在 `corpus/eval/questions.yaml`，21 题，每题写清楚「正确答案在哪一篇的哪一页 / 哪一节」。
改标注不会被代码反向影响，数字与标注一一对应。

## 9. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `ModuleNotFoundError: powercontext` | 没激活虚拟环境 | 确认 `which python` 指向 `.venv` |
| 启动报端口占用 | 8765 被占 | `--port 8766` |
| 导入后 `0 篇` | 资料目录为空或后缀不支持 | 看 `init` 输出的「跳过」行 |
| PDF 抽取为空 | 扫描件没有文本层 | 先 OCR 成文本，或改用 `.md` |
| 中文检索命中率低 | 语料是英文且术语表没覆盖 | 在 `duban/glossary.py` 加一行术语 |
| 评测 Hit@3 低于 README | 换过语料 | 标注必须跟着语料改，指标才有意义 |
| Windows 控制台中文乱码 | 代码页不是 UTF-8 | `chcp 65001` 或用 Windows Terminal |

## 10. 卸载 / 重置

```bash
rm -rf .runtime records/db records/memory records/eval
```

`corpus/` 与源码不受影响。
