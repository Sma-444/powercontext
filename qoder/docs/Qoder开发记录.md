# Qoder 开发记录（执行手册 + 记录模板）

> 这份文档解决一个问题：**Qoder 赛题要求「主要开发工作必须在 Qoder 中完成」，而本项目当前的
> 代码是先用 DSH 打底、在开发机上验证过的。** 所以提交前必须在 Qoder 里补一段**真实的**
> 开发过程，并且留下可核对的记录。
>
> 记录不能编。下面给的是「在 Qoder 里做哪些真实迭代、每步截什么图、怎么归档」，
> 照着做完就是一份经得起核对的开记录。

---

## 0. 先明确三条硬要求

| 要求 | 出处 | 满足方式 |
| --- | --- | --- |
| 主要开发工作在 Qoder 中完成 | 题面 2.1 | 用 Qoder 完成下面 6 个迭代任务，改动进同一个仓库 |
| 保留开发过程记录 | 题面 2.1 / 提交材料 | 每阶段的对话截图 + 文件改动 + 运行结果，归档到 `records/qoder/` |
| 附 Qoder 账号 UID | 提交材料表 | Qoder 客户端 → 账号设置里复制 UID，写进提交表 |

> 官方文档：[Qoder 产品文档](https://docs.qoder.com/qoder/overview)、[Sites](https://docs.qoder.com/qoder/sites)、
> [CLI Sites](https://docs.qoder.com/cli/sites)。个人 Free/Pro 账号都支持静态站点发布。

---

## 1. 准备（30 分钟）

1. 从 <https://qoder.com/download> 安装 Qoder 桌面端（Windows/macOS 均可），登录账号。
   - 比赛发放的 2000 Credits 会显示在账号余额里；
   - **用个人账号**，企业版账号无法把站点设为「任何人可访问」（题面 2.3）。
2. 把仓库放到本地：`git clone <你的仓库地址> qoder && cd qoder`。
3. 在 Qoder 里 `Open Folder` 打开 `qoder/`（项目根，能看到 `duban/`、`web/`、`corpus/`）。
4. 先跑一遍，确认基线可运行：

   ```bash
   python -m venv .venv && . .venv/bin/activate
   pip install -r requirements.txt
   python -m duban init && python -m duban ask "Raft 的 Figure 8 说明了什么问题？"
   ```

5. 建一个归档目录：`mkdir -p records/qoder`。后面每步的截图都放这里，命名用
   `01-需求拆解.png`、`02-索引层.png`……，方便评审按顺序看。

## 2. 六个迭代任务（每个都能独立验收）

> 每个任务的结构：**给 Qoder 的提示词 → 验收标准 → 截图点**。
> 提示词可以直接粘贴；如果 Qoder 一次没做对，就把它跑出来的失败信息贴回去继续对话——
> 这些「失败 → 修正」的过程恰恰是评审最想看的部分，不要删。

### 任务 1：让 Qoder 读懂现有架构（不写代码）

**提示词**

```
读一下这个仓库：duban/ 是检索与记忆模块，web/ 是前端，corpus/ 是示例语料。
请用不超过 400 字说明：一次提问从 HTTP 请求进来，到返回带引用的回答，中间经过哪些函数？
重点说清楚 seekdb 和 PowerContext 分别在哪个环节被调用。
不要改任何代码，先给我你的理解。
```

**验收**：它的描述与 `docs/技术结合.md` 一致（检索走 `CorpusStore.search`，
记忆走 `Memory.snapshot()`；答句由 `build_answer` 从原文抽取）。

**截图点**：Qoder 回答的整段文字（证明它确实读过仓库，而不是泛泛而谈）。

---

### 任务 2：新增 `.docx` 资料支持（真实缺口）

现在只支持 `.md` / `.txt` / `.pdf`。同学的真实资料里 Word 讲义很常见。

**提示词**

```
给 corpus 增加 .docx 支持：
1. 在 duban/corpus.py 里识别 .docx，用 python-docx 逐段读取；
2. 按标题（Heading 样式）切小节，锚点仍用行号区间；
3. 没有标题时整篇按 900 字窗口切；
4. 在 requirements.txt 加上 python-docx 的固定版本；
5. 在 tests/test_corpus.py 补一个用例：构造一个小 docx，断言切出的 chunk 有 section 且 body 是原文子串。
改完把 pytest 跑一遍，把结果贴给我。
```

**验收**：`python -m pytest` 全绿；`corpus/` 里放一个 `.docx` 后 `duban ingest` 能入库。

**截图点**：Qoder 修改 `corpus.py` 的 diff + 新增测试 + pytest 输出。

---

### 任务 3：回答导出为 Markdown（真实需求：贴进组会纪要）

**提示词**

```
给 CLI 加一个命令：
  python -m duban export --question "..." --out records/export/answer.md
要求：
1. 复用现有的 ask 流程（不要另写一套检索）；
2. 导出的 md 包含：问题、每条要点（带 [出处](path#page) 链接）、引用清单；
3. 目录不存在时自动创建；
4. 在 tests 里补一个用例，断言导出文件里出现至少一个 path#anchor。
```

**验收**：导出文件能直接贴进 Markdown 编辑器，链接可点回原文。

**截图点**：命令执行 + 打开导出文件的截图。

---

### 任务 4：前端加「按文档过滤」

**提示词**

```
在 web/ 里加一个文档过滤：
1. 提问框左边加一个下拉，选项来自 /api/state 的 documents（第一项是「全部资料」）；
2. 选中某篇后，/api/ask 请求里带上 doc_id，后端只在该文档内检索；
3. 后端：给 PrepareContextRequest 类似的参数留出 doc_ids，透传到 CorpusStore.search；
4. 过滤生效时，回答上方显示「仅在这篇资料内检索」的提示条；
5. 不选时行为与现在完全一致。
```

**验收**：选中某一篇后，所有引用都来自这篇；清空后恢复。

**截图点**：下拉选中 + 回答里引用全部指向同一篇的截图。

### 任务 5：修一个真实缺陷（引用定位偏移）

已知问题：PDF 长页会被切成多个窗口（`p005`、`p005-1`…），界面里点引用只按页号取回，
展示的是整页而不是窗口那一段；`anchor` 带后缀时应该精确定位到该窗口。

**提示词**

```
duban/service.py 的 resolve() 目前只按页号取回所有 chunk，再按 anchor 匹配；
但 anchor 形如 p005-1 时，page 解析出来是 5，chunks 里可能包含 p005 与 p005-1 两段。
请：
1. 让 resolve() 先按 anchor 精确匹配，匹配不到才回退到整页；
2. 补一个测试：构造两个同页 chunk，断言 resolve("…", "p005-1") 返回的是第二段；
3. 说明修改前后的行为差异。
```

**验收**：测试通过；界面上点 `#p005-1` 只显示那一段。

**截图点**：Qoder 对缺陷原因的分析 + 修改后的测试结果。

## 5. 常见坑

| 坑 | 说明 |
| --- | --- |
| 企业版账号发布不了公开站点 | 题面 2.3 明确要求「任何人都可访问」，用个人账号 |
| 只让 Qoder 写文档、不写代码 | 评审会看「主要开发工作」是否在 Qoder；至少要覆盖索引/检索/记忆/前端中的多数 |
| 删掉失败的对话 | 失败与修正比一次成功更有说服力，保留 |
| 截图只截结果 | 要截到提示词、文件名、diff、运行输出，才叫「开发记录」 |
| 用 Qoder 改完不回跑测试 | 每次改动后跑 `pytest`，把结果记进表里 |
| 站点发布后没检查公开访问 | 用无痕窗口打开一次，确认未登录可访问 |

## 附：如果你想从零在 Qoder 里重建

不建议（现有实现有 21 题评测与 9 个测试兜底，重建会丢验证），但如果要，
按 `duban/` 的模块顺序拆任务即可：

1. `corpus.py`：读 md/txt/pdf，切块保留位置；
2. `store.py`：建表 + NGRAM 全文索引 + 增量同步；
3. `retrieve.py`：多路召回 + 重排；
4. `answer.py`：句子级抽取作答；
5. `memory.py`：四类 artifact 读写；
6. `service.py` + `cli.py`：装配；
7. `server.py` + `web/`：界面；
8. `tests/`：切块、引用回查、记忆重启、增量导入。

每一步都让 Qoder 先写测试再写实现，验收标准用 `pytest` 和 `duban eval` 的数字。
